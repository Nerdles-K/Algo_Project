Problem & Motivation

The Echo Chamber Problem

  • Recommendation feeds trap users in filter bubbles
  • You only see content your immediate network already likes
  • Result: narrowing perspectives, declining content diversity
Given a social graph of users and videos, recommend content that is socially close (BFS) but globally influential (PageRank) — balancing personalization with diversity.

Algorithm 1 — Candidate Recall

BFS — Multi-hop Traversal

start: logged-in user's graph node
hop 1  direct friends        (user→user edges)
hop 2  friends-of-friends
hop 3  their watched videos   (user→video edges)
  • Output: candidate video set reachable within K hops
  • Provides the social distance signal — how many hops from you to a video

Time complexity O(V + E) ≈ O(1,428) — sub-millisecond on our dataset.

Algorithm 2 — Global Influence

PageRank — Video Importance

PR(v) = (1−d)/N + d · Σ PR(u)/out(u)
d = 0.85 · converges in ~20–30 iters · sink handling

Full-graph PageRank

All edges — social + watch + related

Watch-graph PageRank

Only user→video & video→video — reflects actual viewing

A live prMode toggle lets the demo switch modes and watch the ranking shift.

Algorithm 3 — The Recommendation

Composite Scoring

finalScore(v) = α·(1 / Dijkstra_dist(u,v)) ← social closeness + β·normalizedPageRank(v) ← global influence + γ·normalizedPopularity(v) ← views + likes α + β + γ = 1 (auto-normalized from 3 sliders)

Weighted Dijkstra distance

watch = 0.1 (strong) · similar = 0.5 · social = 1.0 (weak)

Log-scaled popularity

0.6·log(1+views)/log(1+max) + 0.4·log(1+likes)/log(1+max)

Defaults α=0.5 β=0.3 γ=0.2. Watched videos excluded; dead/private thumbnails filtered out.

Algorithms 4 & 5 — Diversity & Discovery

LCC — Echo Chamber Detection

  • Local clustering coefficient per user
  • High clustering = tight bubble

Low Medium High

Each user sees their own score; admins see the all-users table.

Friend Recommendation

  • Candidate users within 2 hops
  • Score = shared neighbours + Dijkstra + PageRank + popularity
  • "People you may know" ranked list

Follow/Unfollow persists a social edge to DB and the in-memory graph.

NEW Per-friend recommendations: expand any friend to see what their graph position would recommend — composite scoring run from their node.

Results & Reflection

What we built

Delivered

  • Full-stack app in 3 weeks: Spring Boot + Postgres + Vue 3 + JWT
  • 6 algorithms: BFS, PageRank ×2, Composite, LCC, Friend Rec
  • < 50 ms per request on a 483-node graph · 47 unit tests green

Lessons learned

  • Heterogeneous graphs need careful BFS scoping
  • Watch-graph vs full-graph PageRank differ significantly
  • Production concerns (auth, CORS, dead-video filtering) ≈ +30% effort

Future directions

Larger dataset (10k+ nodes) · collaborative filtering · temporal decay (recent watches weighted higher)
